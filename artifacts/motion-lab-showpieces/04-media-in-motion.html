01

orbital-gallery

3D ring · inertia

Nine media cards on a perspective ring. Grab and flick it — the ring carries momentum and coasts to a stop; the front card sharpens and scales while the rest fall back into haze. Click any card to spring it to the front.

— — / — drag · flick · wheel-x · arrows

Niche

Grid galleries read as inventory; a ring with momentum reads as a collection you handle. Built for template showcases, artwork portfolios and case-study switchers where six to twelve items deserve equal billing — the category that drives reactbits' circular-gallery traffic.

Choreography

  1. Idle drift — ring eases toward 0.14 rad/s after 2.5 s without input.
  2. Grab — pointer locks 1:1 at 0.0045 rad/px; release velocity sampled with a 25% EMA.
  3. Coast — flick clamped to ±6 rad/s, decays as v·e^(−2.2t). A hard flick spins roughly two revolutions.
  4. Focus — click or arrow key springs to the nearest equivalent angle (k=26, c=9.5, slightly under-damped).
  5. Depth cue — per frame from cos θ: scale 0.94→1.06, dim 0→0.78, blur 0→2.2 px in 0.25 px steps.

Props API

interface OrbitalGalleryProps {
  items: MediaItem[]        // 6–12 cards
  radius?: number          // px, auto from card width
  autoRotate?: number      // rad/s, default 0.14
  friction?: number        // 1/s decay, default 2.2
  dimRear?: number         // 0–1, default 0.78
  blurRear?: number        // px, default 2.2
  onFocus?: (item: MediaItem,
    index: number) => void
}

A11y & perf

  • Stage is a focusable group; ← / → rotate one card with the same spring. Front card announced via the caption bar (aria-live polite in the React port).
  • Reduced motion: no drift, no inertia — drag maps directly, arrows jump instantly.
  • Only rotateY / translateZ / scale change per frame — fully composited; blur quantized to 0.25 px so the filter string rarely invalidates.
  • rAF stops the moment the stage leaves the viewport.
02

flow-warp-image

canvas mesh · springs

A 32×20 spring mesh over a rendered dusk scene. Sweep across it and the surface parts around the cursor like liquid, snapping back elastically; leave the frame and it throws a radial splash. It swells on its own while idle.

Field Study 12
Ridgeline, dusk
sweep the surface · exit for a splash

Niche

Cursor-reactive imagery is the most-shared effect category on component showcases. This one earns hero sections, gallery covers and 404 pages: the photo stays legible at rest and only liquefies where the pointer moves, so it works over real product art.

Choreography

  1. Rest — 33×21 grid nodes at zero offset; the scene is pre-rendered once to an offscreen canvas.
  2. Push — nodes within a 140 px radius get an impulse away from the pointer, gain 260 + 0.45·|pointer velocity|, falloff (1−d/R)².
  3. Return — per-node spring, k=90, c=8, dt-integrated; the wake ripples for ~700 ms.
  4. Splash — on pointer exit, a one-shot radial impulse (230 px radius) blooms from the last position.
  5. Idle swell — after 3 s a virtual pointer rides a Lissajous path so the surface never dies.

Props API

interface FlowWarpImageProps {
  src: string | HTMLCanvasElement
  grid?: [number, number]  // default [32, 20]
  stiffness?: number       // default 90
  damping?: number         // default 8
  radius?: number          // px, default 140
  strength?: number        // gain, default 1
  splashOnLeave?: boolean  // default true
  idleWave?: boolean       // default true
}

A11y & perf

  • Keyboard: focus the stage, arrows steer a ripple point, Space fires a center splash. The effect is decorative — the image itself carries the alt text.
  • Reduced motion: renders the still image, physics loop never starts.
  • 640 sub-rect drawImage calls per frame from one offscreen source; DPR capped at 2. No per-pixel work, no getImageData.
  • touch-action pan-y: horizontal strokes warp, vertical swipes still scroll the page. Loop pauses offscreen.
03

velocity-marquee

scroll-reactive · dual row

Two counter-rotating rails that feed on your scroll velocity: shove the page and they surge and shear, stop and they settle back to a calm drift. Hover any card to slow its row and lift it out of the stream.

scroll the page fast boost 1.00×

Niche

Logo walls and media rails are dead weight until they acknowledge the user. A velocity-reactive marquee makes customer-logo sections, gallery teasers and footer reels feel wired into the page — the scroll is the throttle.

Choreography

  1. Drift — rows glide at 36 px/s in opposite directions, offsets wrapped modulo half the track width.
  2. Charge — page scroll velocity is smoothed with an 8 Hz EMA; boost = 1 + min(|v|·0.006, 5).
  3. Shear — skewX eases toward clamp(v·0.012, ±10°) at 6 Hz, signed by row direction.
  4. Relax — boost and skew bleed off over ~600 ms once scrolling stops.
  5. Hover — the row under the pointer eases to 0.25× speed; the card lifts −6 px, scale 1.04, 220 ms.

Props API

interface VelocityMarqueeProps {
  rows: MarqueeRow[]       // items + direction
  baseSpeed?: number      // px/s, default 36
  velocityGain?: number   // default 0.006
  maxBoost?: number       // default 5
  maxSkew?: number        // deg, default 10
  hoverSlow?: number      // default 0.25
  pauseOffscreen?: boolean // default true
}

A11y & perf

  • Duplicated track content is aria-hidden in the React port; one canonical list stays in the DOM for readers.
  • Reduced motion: rows freeze at rest offsets; every item remains hoverable and focusable.
  • One translate3d + skewX per row per frame; card lift is a CSS transition, so hover costs nothing in the rAF loop.
  • Scroll velocity is sampled inside the loop (no scroll listener churn); loop pauses offscreen.
04

filmstrip-scrub

timeline · spring playhead

Twelve generated stills of one valley, dawn to midnight. Drag or hover the strip and the big preview scrubs through them like video, with a spring-loaded playhead, frame ticks and a live 24 fps timecode. It scrubs itself when you leave it alone.

00:00:00:00 dawn
drag or hover the strip

Niche

Product tours and changelogs want the feel of scrubbing a video without shipping one. A filmstrip of stills with a springy playhead covers feature timelines, process breakdowns and before-to-after sequences at a fraction of the bytes.

Choreography

  1. Idle scrub — the target position ping-pongs at 0.9 frames/s, so the page moves before anyone touches it.
  2. Seek — hover or drag sets the target; the playhead chases it with a spring (k=90, c=16, ζ≈0.84) — it lands with one soft overshoot.
  3. Morph — preview crossfades frame ⌊p⌋ into ⌈p⌉ by the fractional part; adjacent stills share geometry so the blend reads as time passing, not a dissolve.
  4. Readout — timecode derives from p at 24 fps; phase label (dawn → night) switches with the sun position.
  5. Resume — autoplay returns 3 s after the last interaction.

Props API

interface FilmstripScrubProps {
  frames: FrameSource[]    // 8–24 stills
  fps?: number            // timecode base, 24
  idleSpeed?: number      // frames/s, 0.9
  spring?: { stiffness: number
    damping: number }     // 90 / 16
  hoverScrub?: boolean    // default true
  loop?: boolean          // ping-pong, true
  onFrameChange?: (i: number) => void
}

A11y & perf

  • The strip is a real slider: focusable, arrow keys step one frame, Home/End jump to the ends, aria-valuenow tracks the frame.
  • Reduced motion: no autoplay, no spring — the playhead and preview snap directly to the pointer or key press.
  • All 12 frames render once to offscreen canvases; per frame the preview is two drawImage calls. Playhead moves via left on a composited layer.
  • Loop pauses offscreen; thumbnails are static canvases.
05

compare-reveal

before / after · elastic

Wireframe pass on the left, finished render on the right — the same scene, same geometry. The divider chases your pointer with a hint of elastic resistance, demos itself with a full sweep on first sight, and double-click snaps it home to 50%.

v1 wireframe v2 render
drag · double-click for 50%

Niche

Design-refresh announcements, image-pipeline docs and photo-editing landing pages all need a comparator, and most ship a lifeless input range. The self-demonstrating sweep teaches the interaction with zero tooltips.

Choreography

  1. Intro sweep — on first viewport entry, once: 50 → 96 → 4 → 50 over 2.6 s, cubic ease per leg. Replays only if it was interrupted.
  2. Drag — the target tracks the pointer exactly; the divider follows through a spring (k=140, c=18, ζ≈0.76). The lag reads as elastic resistance, the release as a soft snap.
  3. Snap — double-click sets the target to 50%; the same spring carries it home with one overshoot.
  4. Labels — v1 / v2 chips fade out when their side narrows past 12%.
  5. Signature — the coral handle glow is this page's single signature-color moment.

Props API

interface CompareRevealProps {
  before: ReactNode
  after: ReactNode
  initial?: number         // %, default 50
  introSweep?: boolean    // once, default true
  elasticity?: { stiffness: number
    damping: number }     // 140 / 18
  labels?: [string, string]
  snapOnDoubleClick?: number // %, 50
  onChange?: (pct: number) => void
}

A11y & perf

  • The handle is a native button with role slider: arrows move 2%, Shift+arrows 10%, aria-valuenow live.
  • Reduced motion: no intro sweep, no spring — the divider maps 1:1 to input.
  • Reveal is a clip-path inset on a composited layer; both scenes are painted once per resize/theme, never per frame.
  • Intro and spring run in one rAF loop that stops offscreen and when settled.
