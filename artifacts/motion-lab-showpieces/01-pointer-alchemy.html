Pointer Alchemy

Five cursor-physics showpieces for the catalog's first pointer category. The premise: treat the cursor as a physical object — with mass, heat, and optics — instead of a hit-testing dot. Every demo below runs real spring integration with delta-time, stays alive at idle, pauses offscreen, and degrades to a deliberate static state under reduced motion.

01 / 05attraction field

magnetic-dock

A launcher dock where icons live inside a shared gaussian attraction field. The pointer doesn't trigger per-icon hover states — it bends one continuous field, so neighbors cascade naturally and the whole bar feels like liquid under a magnet.

Workspace
8 apps · field radius 78px
Compose
sweep the dock · springs k420 / c26 reduced motion · hover lifts, no springs

Niche

The macOS dock effect is the most requested "how did they do that" pattern in landing-page navs, floating toolbars, and app switchers — and almost every open clone animates each icon independently, which reads as stiff and twitchy.

Modeling one shared field instead gives free neighbor cascade and makes the component usable for horizontal navs, emoji pickers, and avatar strips, not just docks.

Choreography

  1. Field. Per frame, each icon samples a gaussian exp(-d²/2σ²) of its distance to the pointer, σ = 78px, attenuated by vertical distance so the field dies above the bar.
  2. Response. Influence drives three springs: scale to 1 + 0.95·inf (k 420, c 26, ζ≈0.63), lift to −40px (k 360, c 22), and lateral drift 0.13·d·inf toward the pointer — that drift is what makes it liquid.
  3. Tooltip. Above 0.55 influence, the label chip springs horizontally (k 340) to the winning icon and fades in over ~120ms.
  4. Idle. No pointer: a virtual pointer sweeps the bar on a 11.4s sine at 42% strength, so the dock breathes on load.

Props API

interface MagneticDockProps {
  items: DockItem[]
  magnetRadius?: number   // σ px · 78
  maxScale?: number       // 1.95
  lift?: number           // px · 40
  stiffness?: number      // 420
  damping?: number        // 26
  idleWave?: boolean      // true
  tooltip?: boolean
  onSelect?: (id: string) => void
}

A11y & perf

  • Reduced motion: springs off; icons keep a 120ms CSS hover lift so the affordance survives.
  • Icons are real buttons; keyboard focus rings sit outside the transform so they never scale.
  • Transform-only animation; base positions cached from offsetLeft (transform-immune) so there is zero layout feedback.
  • Touch: the field tracks the finger during pan; taps still activate. rAF loop stops via IntersectionObserver when the stage scrolls out.
02 / 05velocity plume

cursor-comet

A canvas particle comet that reads pointer velocity, not just position. Slow movement holds a tight ember; a fast flick ionizes into a long azure-to-cyan tail with coral sparks at peak speed. Untouched, the particles fall into an ambient orbit so the stage never plays dead.

Flick fast. Then drift.
tail length ∝ pointer velocity
240-particle pool · additive blend reduced motion · static orbit rendering

Niche

Cursor trails are the single most shared component class on reactbits — they sell a site's craft in the first half-second. Most are constant-length snakes; making the plume velocity-reactive is what separates "effect" from "physics."

Target placements: hero sections, 404s, changelog pages, anywhere the brand wants visible energy without layout cost.

Choreography

  1. Emission. Spawn rate 2→22 particles/frame, linear in pointer speed (clamped at 3000 px/s). Particles inherit 22% of pointer velocity, reversed, plus radial jitter.
  2. Flight. Drag v ·= e^(−2.2·dt); life 0.5–1.4s scaling with launch speed. Color crossfades azure→cyan across life; every particle is a pre-rendered radial-gradient sprite drawn with lighter compositing.
  3. Ionization. Above 900 px/s, short-lived coral sparks spawn at the head — the page's single coral moment, reserved for peak energy.
  4. Idle. Pointer gone: a virtual head wanders a Lissajous path and particles feel a soft radial spring toward a 62px orbit ring, so the comet coils into a living ember.

Props API

interface CursorCometProps {
  particleBudget?: number  // 240
  velocityGain?: number    // 0–1 · 0.22
  drag?: number             // 2.2 /s
  headColor?: string       // token azure
  tailColor?: string       // token cyan
  sparkColor?: string      // token coral
  sparkThreshold?: number  // px/s · 900
  idleOrbit?: boolean      // true
}

A11y & perf

  • Purely decorative: canvas is skipped by AT; underlying content stays interactive.
  • Reduced motion renders one static frame — an orbit ring of glow dots — re-drawn only on theme change or resize.
  • Fixed pool (no GC churn), DPR-capped at 2×, sprite drawImage instead of per-particle gradients or shadowBlur.
  • Sprites rebuilt from getComputedStyle tokens on theme flips; loop hard-stops offscreen via IntersectionObserver, independent of document.visibilityState.

lens-card

A refraction lens that floats over a metrics grid: content under the glass magnifies 1.35× with a chromatic fringe, and the background grid lines physically bend around the lens edge. Niche

Dashboards and pricing grids are dense by design; a lens gives momentary local zoom without a modal or a layout shift. As a marketing surface it's a signature move — Vercel- and Linear-class sites use optical tricks exactly like this to make static data feel machined.

The clip-path approach means any children work: text, charts, images, code.

Choreography

  1. Follow. Lens center springs to the pointer (k 300, c 27 → ~90ms of lag), which sells glass mass. Radius springs 0→104px on entry with mild overshoot.
  2. Refraction. A cloned layer scales 1.35× from origin 0,0 with translate = (1−s)·lens, so the point under the lens center stays optically fixed. Clip: circle(104px at x y).
  3. Chromatic fringe. A second clone at 1.38×, offset +2.2px, hue-rotated 150° and screen-blended at 45% — reads as edge dispersion for the cost of one extra composite.
  4. Grid bend. Canvas grid lines displace radially by a gaussian centered on the lens rim (σ 60px, 16px amplitude), tinted azure within 1.7R.
  5. Idle. The lens drifts on a slow two-frequency orbit so the refraction is visible before any input.

Props API

interface LensCardProps {
  children: ReactNode
  radius?: number         // px · 104
  magnification?: number  // 1.35
  chromatic?: number      // px · 2.2, 0 = off
  lag?: { stiffness: number; damping: number }
  gridBend?: boolean      // true
  idleDrift?: boolean     // true
  showRing?: boolean      // true
}

A11y & perf

  • The magnified clone is aria-hidden and inert-equivalent (pointer-events none); AT reads the base layer once.
  • Reduced motion parks the lens center-stage, static — the zoom affordance remains, the chase does not.
  • Clip-path + transform are compositor-side in Chromium; the only CPU work is the grid canvas (~90 polylines).
  • Touch: lens rides the finger; base tiles remain tappable because overlay layers never intercept events.

Niche

Dual-layer reveals are how design tools, dev tools, and API companies say "we respect the craft underneath." Flashlight heroes trend on every launch site aggregator, but nearly all reveal a plain dark layer — revealing an annotated blueprint twin gives the effect an actual story.

Also works inverted: reveal the finished render over a wireframe base for before/after product shots.

Choreography

  1. Carry. Torch position springs after the pointer (k 260, c 24) — enough lag to feel hand-held rather than parented.
  2. Flame. Radius breathes: 175px base + two incommensurate sines (9Hz × 5px, 23Hz × 2.5px) for an organic flicker; a screen-blended cyan glow rides on top.
  3. Mask. The blueprint layer is masked by radial-gradient(#000 0 52%, transparent 100%) whose center/radius live in CSS custom properties — JS writes three numbers per frame, never a new string of layout.
  4. Idle. Unattended, the torch patrols a Lissajous path across the hero, pausing near the annotated card — a built-in product tour.

Props API

interface TorchRevealProps {
  base: ReactNode
  reveal: ReactNode        // blueprint layer
  radius?: number          // px · 175
  softness?: number        // 0–1 · 0.48
  flicker?: number         // 0–1 · 0.35
  lag?: { stiffness: number; damping: number }
  idlePatrol?: boolean     // true
  reducedFallback?: "split" | "off"
}

A11y & perf

  • The blueprint twin is aria-hidden; the readable hero is always the base layer, torch or no torch.
  • Reduced motion swaps to a static 55/45 split with a dashed divider — the "two layers" story survives without any tracking.
  • Mask position updates via custom properties on a composited layer; the flicker costs one mask re-raster per frame, measured well under budget at 480px stages.
  • Uses alpha masks only. SVG luminance masks with gradient content are a silent no-op in Chromium — this is a hard rule for the ported component.
05 / 05metaball bloom

gooey-actions

A floating action button that blooms into five satellites through a gooey metaball merge — blur + alpha-contrast SVG filter under the hood, underdamped springs for the overshoot, and per-satellite magnetic hover so each action leans into the cursor before commit.

One button, five intents
tap the core · goo: blur 10 → alpha ×24 −12
Reply
click the core · springs k230 / c13 · ~18% overshoot reduced motion · instant open, fade only

Niche

Speed-dial FABs are everywhere in product UI — messaging, docs, mobile-first dashboards — and they almost always animate as disconnected circles. The metaball merge makes the button read as one liquid organism dividing, which is the moment people screenshot.

The same goo field powers menu reveals, reaction pickers, and multi-cursor presence blobs.

Choreography

  1. Bloom. On toggle, satellites spring from the core to a 118px arc (−160°→−20°) with 45ms stagger. Springs k 230, c 13 → ζ≈0.43, ~18% overshoot — the goo stretches, necks, then snaps free.
  2. Goo. Filter chain: feGaussianBlur stdDeviation 10 → feColorMatrix alpha row 0 0 0 24 −12. Solid blobs animate under the filter; crisp icons live on an unfiltered twin layer sharing the same transforms.
  3. Magnet. Within 52px, a satellite leans up to 35% of the gap toward the pointer and scales to 1.16 — commit feels pre-confirmed before the click.
  4. Idle. Closed, two ember blobs orbit the core through the goo field (merging and splitting), and the core breathes at 4% amplitude. First interaction retires an auto-peek that fires every ~7s.

Props API

interface GooeyActionsProps {
  actions: ActionItem[]   // 3–6
  radius?: number         // px · 118
  arc?: [number, number]  // deg · [-160,-20]
  stagger?: number        // ms · 45
  stiffness?: number      // 230
  damping?: number        // 13
  magnetRange?: number    // px · 52
  open?: boolean          // controlled
  onOpenChange?: (open: boolean) => void
}

A11y & perf

  • Core is a button with aria-expanded/aria-haspopup; satellites get tabindex 0 + labels only while open, Escape closes and returns focus.
  • Reduced motion keeps the goo look but opens instantly with a fade — no springs, no orbiting embers.
  • The filter costs one fixed-size offscreen surface; blobs animate with transforms only, so the blur re-runs but never re-lays-out. Icons stay crisp because they never enter the filtered subtree.
  • Touch: first tap opens, second tap on a satellite commits; magnetic lean is pointer-only. Loop parks offscreen via IntersectionObserver.
