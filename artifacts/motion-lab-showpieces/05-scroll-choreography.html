Niche

The opening move of nearly every modern product site — Linear, Vercel and Stripe all begin by zooming a framed product shot into a full-bleed surface. It buys the visitor's first ten seconds with one gesture, one object, and escalating scale.

Choreography

  • 0.00–0.15 frame idles at 45% scale, radius 16px, vignette at 85%; caption 01 held
  • 0.15–0.70 scale 0.45 → 1.0 on easeInOutCubic; translateY 14 → 0px; radius 16 → 0; vignette lifts to 0
  • 0.30–0.80 chart bars grow bottom-up with a 4%-of-progress per-bar stagger
  • 0.34 / 0.70 captions crossfade, 360ms on ease(0.2, 0, 0, 1)
  • progress is lerped toward the raw scroll ratio at λ = 10/s, so scrubbing feels damped, never raw

Props API

interface StickyZoomHeroProps {
  children: React.ReactNode;
  stages: { title: string;
    body: string }[];  // 2–4 beats
  startScale?: number;   // 0.45
  scrollLength?: number; // 3.2 stages
  radius?: number;       // 16
  vignette?: boolean;    // true
  smoothing?: number;    // λ 10/s
  onStageChange?: (i: number) => void;
}

A11y & perf

  • Reduced motion pins the scene at 100% with the final caption readable; the stage stays scrollable as plain content
  • Stage is a focusable region — arrow keys scrub it; wheel passes through to the page at both ends
  • Only transform / opacity animate; border-radius writes are quantized to whole pixels (≤ 16 paints per full pass)
  • rAF stops via IntersectionObserver when the stage leaves the viewport

Niche

Depth headers sell "a world behind the glass" — hero sections and feature interludes where a flat gradient feels cheap. Layered travel plus pointer drift reads as production value, and every layer here is generated: no image assets, fully token-themed.

Choreography

  • progress = stage position through the viewport, measured with getBoundingClientRect every frame, lerped at λ = 8/s
  • layer travel = (0.5 − p) × 180px × depth; depths 0.06 / 0.16 / 0.32 / 0.52 / 0.78 back to front
  • pointer parallax: normalized cursor lerped at λ = 4/s → ±26px × depth horizontal, ±14px vertical
  • depth of field: far-ridge blur 0 → 2.5px as the scene centers, quantized to 0.2px steps to avoid per-frame filter churn
  • floating cards add a 6–8s CSS float loop, phase-offset per card — the ambient life on load

Props API

interface ParallaxLayer {
  node: React.ReactNode;
  depth: number;   // 0 far – 1 near
  blur?: number;   // max px of DOF
}
interface DepthParallaxSceneProps {
  layers: ParallaxLayer[];
  range?: number;      // 180px
  pointer?: boolean;   // true
  pointerStrength?: number; // 26
  depthOfField?: boolean;
  height?: number | string;
  smoothing?: number;
}

A11y & perf

  • Purely decorative: the scene carries a single role="img" label; all inner layers are aria-hidden
  • Reduced motion freezes the centered composition with zero blur and no pointer response
  • Layers move on translate3d only; the blur write is change-gated; no internal scroller, so no scroll trap exists
  • rAF pauses offscreen; layers are 114% oversized so travel never reveals edges

Niche

Chaptered storytelling — pricing pages, changelogs, "how it works" walkthroughs — needs harder cuts than crossfades. Clip-path wipes carry direction and intent, and the lit leading edge makes each cut feel authored rather than triggered.

Choreography

  • 0.06–0.34 angled sweep: a polygon edge with 12% slant slides left → right on easeInOutCubic; the edge bar tilts 8° and peaks at sin(π·t)
  • 0.39–0.64 iris: circle() grows from 78% / 30% to the full stage diagonal; a scaled ring hugs the radius
  • 0.70–0.94 curtain: inset() opens from the center line; twin glow edges travel outward symmetrically
  • ≈5% dwell gaps between wipes give each chapter a held beat; progress lerped at λ = 9/s

Props API

interface WipeSection {
  content: React.ReactNode;
  wipe: "sweep" | "iris" | "curtain";
  origin?: [number, number]; // iris
  accent?: string;
}
interface MaskWipeSectionsProps {
  sections: WipeSection[];
  scrollLength?: number; // 3.8
  edgeGlow?: boolean;    // true
  dwell?: number;        // 0.05
  smoothing?: number;
  onSectionChange?: (i: number) => void;
}

A11y & perf

  • Reduced motion collapses the sticky stack: panels render as plain stacked sections, all four fully readable and scrollable
  • Basic-shape clip-path animates on the compositor in Chromium; only the currently active wipe's style is written each frame
  • Stage is keyboard-scrollable and passes wheel through at both ends (overscroll-behavior: contain + edge relay)
  • Edge glows are transform + opacity only; rAF pauses offscreen

Niche

Stats bands are usually fire-and-forget: they count once and go inert. Binding them to scroll turns them into scrubbable evidence — scroll back and 48,210 unwinds to zero. That reversibility is the moment visitors demo to their team.

Choreography

  • stat i activates at p = 0.06 + 0.12i over a 0.55 window; progress lerped at λ = 9/s
  • each digit column rolls a 0–9 strip, most-significant first, 5.5% stagger, easeOutCubic
  • overshoot: +0.35 rows via sin(π·t) across the last 35% of each digit — passes the target, settles exactly on it
  • 0.52–0.78 the coral underline draws left → right (pathLength 1 + dashoffset) — this page's single coral moment
  • sparklines trace inside each stat's window; area fill fades to 50%; all of it a pure function of progress, so reversing scroll rewinds perfectly

Props API

interface CountStat {
  value: string;  // "48,210" — separators pass through
  label: string;
  suffix?: string;
  spark?: number[];
}
interface ScrollCountStatsProps {
  stats: CountStat[];
  stagger?: number;    // 0.055
  overshoot?: number;  // 0.35 rows
  underline?: "signature" | "none";
  scrollLength?: number; // 2.6
  smoothing?: number;
}

A11y & perf

  • True values live on each stat as aria-label; the rolling strips are aria-hidden decoration
  • Reduced motion renders final values immediately with the underline fully drawn
  • Each column is a fixed-height overflow crop — the roll is one translate3d per column; row height re-measured on resize
  • Digits use tabular-nums so columns never shift; rAF pauses offscreen
05 velocity-skew-feed internal scroll · spring physics

Flick the feed: cards shear and stretch with scroll velocity, then a real spring snaps them back at rest. The meter up top is the proof of physics.

0 px/s peak 0 px/s
flick this feed fast

Niche

Feeds and card grids feel inert during fast scrolling. Velocity-reactive skew — Apple-style rubber physics — makes speed visible and makes the stop feel physical. It carries no information, which is exactly why it must cost nothing: transforms only, and it sleeps at rest.

Choreography

  • velocity = ΔscrollTop / Δt, smoothed at λ = 12/s; target skew = clamp(v × 0.0035, ±6.5°)
  • skew runs through a real spring: s″ = 90(target − s) − 14s′, integrated with frame delta-time
  • cards apply skewY(s) scaleY(1 + |s|·0.008) — shear plus stretch, origin center
  • the needle mirrors smoothed velocity (±2,600 px/s full scale); the peak readout decays at 0.4/s
  • on a hard stop the spring overshoots once by ≈8% and settles in about 420ms — the rubber snap

Props API

interface VelocitySkewFeedProps {
  children: React.ReactNode; // cards
  maxSkew?: number;    // 6.5 deg
  stiffness?: number;  // 90
  damping?: number;    // 14
  stretch?: number;    // 0.008
  meter?: boolean;     // false in prod
  axis?: "y" | "x";
}

A11y & perf

  • Reduced motion disables skew, stretch and the idle pulse entirely — the feed is a plain scroller
  • One transform write per card per frame, transforms only; the loop idles when spring energy falls under threshold and pauses offscreen
  • Wheel passes through to the page at both feed ends; feed is keyboard-scrollable
  • Meter text updates are throttled and tabular-nums so nothing reflows
